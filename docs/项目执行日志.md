### 阶段 2：初版测试集（TTS 合成）与首轮评测

**想法**：用户提出用小米 MiMo TTS 合成测试语音（TTS 免费，比人录音快且可复现）。

**MiMo TTS 接入**（文档 https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis-v2.5）：
- OpenAI 兼容接口：`base_url=https://api.xiaomimimo.com/v1`，`model="mimo-v2.5-tts"`
- 消息格式：user=风格指令，assistant=要合成的文本；`audio={"format":"wav","voice":"Chloe"}`
- 返回 `message.audio.data`（base64 wav）

**首轮结果（32 条，Chloe 音色，78 热词）：句级准确率 81.2%**（去空格/小写归一化口径；初版评测函数因数字转换 bug 报 65.6%，已修复并记录）

失败归因（关键发现）：
- "急停"→`jiking`、"停止运行"→`kingerincine`：**拉丁字符幻觉**
- 近音字：平衡→葵横、停止→葵之、运行→跃行

## 2026-09-15（续）：FunASR 流式版部署与初测

### 流式模型选定与下载
- 选定 `iic/speech_paraformer-large_asr_nat-zh-cn-16k-common-vocab8404-online`（ParaformerStreaming，2pass 在线模型，ModelScope 在架确认）
- 从模型 README 提取官方实时用法：`chunk_size=[0,10,5]`（600ms）、`encoder_chunk_look_back=4`、`decoder_chunk_look_back=1`、`cache` 跨块传递、末块 `is_final=True`

### 踩坑记录
1. **chunk_size 传 int 报错**：`TypeError: 'int' object is not subscriptable`——内部按 `[0,10,5]` 三元组下标取值，必须传列表 `[0,10,5]`（0=历史,10=当前块,5=右文），对应 600ms 步长
2. **返回结构**：每块返回 `res[0]["text"]` 为**新增文字**（增量），需自行拼接；早期误读 `res[0]["value"]` 导致全空
3. **采样率坑（重要）**：TTS 音频 24kHz 直接切块喂入时 chunk_stride 按 16k 计算导致切错位置，"急停"识别成 `QITe`（拉丁幻觉再现）；**scipy resample_poly 重采样到 16k 后恢复正常汉字输出**。教训：进 ASR 前统一重采样 16kHz，作为固定前置步骤

### 流式 vs 离线初步对比（重采样 16k 后，无热词）

| 音频 | 离线 SeACo+热词 | 流式 online |
|---|---|---|
| 流速设为一点零毫升每分钟 | ✓ | ✗ 丢"一点零"（"流速设为三毫升每分钟"）|
| 急停（茉莉） | ✓ 急停 | ✗ 集田 |
| 停止采集（白桦） | ✓ | ✓ |
| 基线稳定了吗（茉莉） | ✓ | ✗ 西线 |
| 怎么排气泡（白桦） | ✓ | ✓（重采样后）|
| 急停（苏打） | ✓ | ✓ |

**初步结论**：
1. 流式链路打通，GPU 上 600ms 块解码约 50~80ms（RTF≈0.1，实时性极好）
2. 流式 online 路径精度低于离线 SeACo（预期内），**热词参数对流式版无显著效果**（实测 hotword='热词表' 传入后关键句无改善）
3. 官方生产推荐即 **2pass**：online 流式先出字（体验层）+ offline 句尾重识别纠正（精度层）——与我们"离线 SeACo 98.3%"正好互补

**正在执行**：~~流式版全量 180 条评测~~ → **已完成**。

### 流式版全量评测结果（180 条，重采样 16k，无热词）

| 版本 | 总体准确率 |
|---|---|
| 离线 SeACo + 109 热词 | **98.3%** |
| 流式 online（无热词） | **64.4%**（冰糖 64.4 / 白桦 60.0 / 苏打 68.9 / 茉莉 64.4） |

失败 64 条集中在**领域术语**：进样→禁样/尽样、峰面积→风面积、柱温→助瘟/主温、抑制器→抑制气、载入→再入、流速→流宿……正是热词表覆盖的词。**结论：流式 online 版本术语识别能力远低于离线 SeACo，且热词参数对其无效，单独不可用。**

### 决策：流式+离线双路组合（2pass 思想，GPU 侧已具备条件）

```
麦克风 → VAD → 流式online(600ms块, 边说边出字, 仅体验层, 不触发执行)
              │ VAD尾点(说完)
              ▼
        离线SeACo+热词(整句重识别, 98.3%, 唯一执行依据) → NLU → 决策 → 仪器
```

- 流式层只做"正在听"的视觉反馈，**永不作为执行依据** → 64.4% 不影响正确性
- 执行层 100% 依赖离线 SeACo（98.3%）→ 端到端正确性不变
- 时延：VAD 尾点 400ms + SeACo GPU 解码 ~100ms + NLU/执行 ~100ms ≈ **0.6~0.8s**，在 1s 预算内
- 现场无 GPU 时（X5 CPU 跑离线 SeACo）：RTF 约 0.3~0.5（2s 句子约 1s 解码），总时延 ~1.5s，仍可接受；X5 部署在 M7 后重新评估

**结果文件**：`tests/asr_testset/results/{streaming_hyp.json, summary_streaming.txt}`
**新脚本**：`funasr_env/streaming_test.py`（流式冒烟，含正确用法注释）

### 附加发现：NLU 拼音纠错的理论上限（W13 的量化依据）

对 64 条流式失败做拼音层分析（pypinyin）：
- **拼音完全相同 47 条 + 高相似 17 条 = 100% 可救**
- 典型案例："开始进样→开始禁样""柱温→助瘟""流速→流宿"全部拼音全同
- **含义**：NLU 层的拼音纠错（W13 设计项）对这类 ASR 错误有完整覆盖能力，是比换模型更便宜的第一道兜底。离线 SeACo 剩余 3 条失败同属此类（怎么/什么 同音）

### 意图规则引擎（NLU L1，设计方案 W13 的实现）

- 参数类 7 个意图：正则模板 + 槽位抽取（流速/柱温/波长/进样量/压力上限/抑制器电流）
- 关键词类 29 个意图：模板关键词匹配
- 拼音纠错兜底：`pypinyin` 转音序列 + difflib 相似度 ≥0.75 采纳
- 数字归一化：中文数字→阿拉伯数字 + "点"→"."（"一点零"→1.0）

**踩坑 2 例**：
1. "点"未转"."导致数值正则断开 → norm() 补 `replace("点",".")`
2. set_temp 正则 `.{0,3}` 抢配"柱温箱温度" → **长模板前置** + 负向环视 `(?!箱)` 排除
